# RePhoto V1 设计文档

## 1. 背景与目标

构建一个 Flutter 跨端应用，支持 Android、iOS、macOS，用于高效整理照片与视频。

核心目标：
- 在移动端通过手势快速处理媒体（照片与视频）
- 使用“回收站”实现软删除与统一最终删除
- 基于时间与地点进行筛选与处理
- 在 macOS 端支持导入文件夹并扫描媒体

## 2. 范围与非范围

V1 范围：
- Android/iOS：读取系统相册媒体（照片+视频），支持最终真实删除
- macOS：仅管理手动导入的目录媒体
- 统一手势交互：左随机、右回看、上删除到回收站、下撤销上次删除
- 时间与地点筛选
- 视频播放
- 回收站角标、回收站列表、批量删除、单项恢复
- 端内独立，不做跨端同步

V1 非范围：
- 账号系统与云同步
- 直接管理 macOS Photos.app
- 智能推荐/AI 分类

## 3. 关键交互定义

主页面手势：
- 左滑：随机加载下一条未在回收站中的媒体
- 右滑：回到上一条已展示媒体（跳过回收站中的媒体）
- 上滑：将当前媒体放入回收站（软删除）
- 下滑：撤销最近一次删除（从回收站恢复）

回收站：
- 顶部或导航处显示回收站图标与角标计数（照片+视频总数）
- 点击进入回收站页面
- 页面支持：
  - 勾选部分媒体恢复（移出回收站）
  - 统一“全部永久删除”

筛选：
- 时间预设：今天、最近7天、最近30天、本月、今年、去年、自定义区间
- 地点层级：国家/省市/区
- 快捷筛选：基于当前媒体
  - 仅看当天
  - 仅看同地点（且同地点过滤受当前时间条件约束）

随机策略：
- 在当前筛选结果集内执行“优先不重复”随机
- 全部看完自动重置
- 支持手动重置随机池

## 4. 架构设计

### 4.1 Domain 层（跨平台核心逻辑）
- `MediaItem`：媒体统一模型（id, type, createdAt, location, uri/path, source）
- `TrashEntry`：回收站条目（mediaId, trashedAt）
- `FilterState`：时间与地点筛选状态
- `RandomPoolState`：`unseen`, `seen`
- `HistoryState`：`displayHistory`, `deleteActionStack`

### 4.2 Data 层（平台接入）
- Android/iOS：系统相册读取与删除接口
- macOS：导入目录扫描与文件删除接口
- 本地存储：回收站、筛选条件、随机池、历史栈

### 4.3 Presentation 层（Flutter UI）
- 主媒体页面
- 顶部筛选组件
- 当前媒体快捷筛选按钮
- 回收站入口（角标）
- 回收站页面

## 5. 数据流与状态机

1. 根据时间+地点生成 `filteredSet`
2. 在 `filteredSet` 上构建随机池：`unseenQueue` 与 `seenSet`
3. 左滑触发随机取样；右滑读取展示历史
4. 上滑写入回收站并记录删除动作栈
5. 下滑从删除动作栈恢复上一条
6. 回收站最终删除调用平台删除能力并更新本地索引

## 6. 平台能力与边界

Android/iOS：
- 可读取媒体、时间、地点（若存在）、播放视频
- 最终删除为系统真实删除
- 受权限、系统确认、云端资源可用性影响

macOS：
- 仅导入目录扫描（照片+视频）
- 最终删除为删除导入目录源文件
- 外部文件变更需失效处理

统一降级：
- 无地点归类“未知地点”
- 删除失败保留在回收站并可重试
- 权限拒绝时提供设置引导

## 7. V1 验收标准

- 时间+地点筛选后，随机只在筛选结果内进行
- 上滑后回收站角标 +1，下滑撤销后 -1
- 右滑回看不会回到已在回收站的媒体
- 回收站恢复后媒体重新进入可处理集合
- 回收站“全部永久删除”后源媒体确实删除
- 视频在主页面与回收站页面可播放
- 无地点媒体可在“未知地点”中处理

## 8. 里程碑

- M1：读取媒体、手势流、回收站软删除/恢复、基础视频播放
- M2：时间地点筛选、快捷筛选、随机池自动/手动重置
- M3：稳定性增强（失败重试、异常处理、性能优化）
