# PhotoTend 宣传站设计

## 1. 背景与目标

为理好相册 PhotoTend 建立一个独立部署的响应式宣传站，服务中国大陆与海外用户。宣传站放在当前 Flutter 仓库的 `website/` 子目录中，使用 Next.js 与 TypeScript 实现，并部署到：

`https://phototend.onemorejack.top`

宣传站需要：

- 清晰表达 PhotoTend “轻松整理，而不是制造清理焦虑”的品牌定位。
- 覆盖桌面与移动浏览器，并提供中文与英文内容。
- 展示手势整理、回收站保护、时间与地点筛选、照片与视频支持。
- 独立展示从手机相册、相机存储卡、外部存储和 macOS 文件夹导入的使用场景。
- 支持用户提交邮箱加入 Waitlist。
- 对已有体验版的平台发送下载邮件，并允许用户在提交成功后安全下载。
- 对尚未开放的平台保存 Waitlist，在版本开放后发送通知。
- 安全保存邮箱，跟踪必要的邮件与下载状态，并支持退订和数据删除。

## 2. 已确认的技术方案

### 2.1 仓库边界

宣传站与 Flutter App 保持在同一个 Git 仓库中：

```text
PhotoTend/
├── android/
├── ios/
├── lib/
├── macos/
├── assets/brand/
└── website/
```

`website/` 拥有独立的 Node.js 依赖、测试、构建和部署配置。网站可以复用仓库中的品牌素材，但不得让 Flutter 和 Next.js 的构建依赖互相污染。

### 2.2 服务组成

- Vercel：Next.js 页面、服务端接口、SEO、下载跳转和 Webhook。
- Supabase Postgres：Waitlist、版本、邮件事件和下载事件。
- Supabase Storage：私有保存 APK、DMG 等安装包。
- Resend：事务邮件、版本通知和邮件状态 Webhook。
- `phototend.onemorejack.top`：生产域名。

管理密钥只存在于 Vercel 服务端环境变量中。浏览器不得直接持有 Supabase service role key、Resend API key、下载签名密钥或 Webhook secret。

## 3. 品牌与内容策略

### 3.1 品牌定位

品牌气质延续现有 PhotoTend 品牌设计：温暖、轻快、克制、可靠。页面不使用垃圾清理、空间焦虑或夸张的效率承诺作为主要驱动力。

品牌主张：

> 理好相册 PhotoTend  
> 轻松整理，留下真正重要的照片。

首屏标题：

> 让整理照片，  
> 变成一件顺手的小事。

首屏说明：

> 用直觉手势快速浏览、保留或移入回收站。  
> 不催你清空相册，只帮你留下真正重要的照片。

首屏表单：

- 输入框：`你的邮箱`
- 平台：`Android`、`macOS`、`iPhone`
- 按钮：`获取体验版`
- 说明：`我们会把适合你设备的下载链接发送到邮箱。不会发送无关邮件。`

如果所选平台尚未开放：

> 这个平台的体验版正在准备中。留下邮箱，开放测试时我们会第一时间通知你。

### 3.2 页面结构

1. 顶部导航与品牌。
2. 首屏价值主张、产品视觉和 Waitlist 表单。
3. 手势整理演示。
4. 外部导入场景。
5. 三个核心能力。
6. 产品理念。
7. 平台和版本状态。
8. 第二个 Waitlist 转化区。
9. 隐私、退订、联系方式、版本与版权页脚。

桌面首屏采用左右分栏。移动端采用单列顺序，先表达价值，再展示产品，再出现表单。核心表单在首屏和页面底部各出现一次，但使用同一数据与状态逻辑。

### 3.3 手势整理

标题：

> 一张一张，轻松理好。

手势说明：

- 左滑：随机看看下一张。
- 右滑：回到刚刚看过的照片。
- 上滑：先放进回收站。
- 下滑：撤销刚才的操作。

保护说明：

> 所有删除都先进入回收站。想清楚之后，再统一处理。

### 3.4 外部导入

此能力作为独立场景区，而不是普通功能卡片。

标题：

> 手机里的，相机里的，  
> 都可以一起理好。

正文：

> 从外部存储导入照片和视频，在 PhotoTend 中集中浏览和整理。无论是一次旅行的手机随拍，还是相机存储卡里的素材，都能从同一个地方开始。

场景标签：

- 手机系统相册
- 相机与存储卡
- 移动存储设备
- macOS 文件夹

所有文案必须与各平台当前真实能力一致。尚未验证的平台或来源不得写成已完整支持。

### 3.5 核心能力

#### 整理不用从头开始

> 按时间和地点筛选，从今天、一次旅行，或者一个熟悉的地方开始。

#### 照片和视频一起看

> 不必在不同工具之间切换，照片、视频和动态照片都能在同一条浏览流中处理。

#### 给反悔留出空间

> 先移入回收站，随时恢复。只有最后确认时，才会永久删除。

### 3.6 产品理念

标题：

> 不是清理任务，是重新看看你的照片。

正文：

> 相册里不只有占用空间的文件，也有忘记整理的日常。PhotoTend 希望把繁重的批量管理，变成几分钟就能完成的小动作。今天理一点，慢慢留下真正想保存的内容。

## 4. Waitlist 与下载流程

### 4.1 表单行为

用户提交：

- 邮箱
- 目标平台
- 当前语言
- 表单来源位置
- 对产品邮件的明确同意

服务端执行：

1. 规范化并校验邮箱。
2. 验证诱捕字段和频率限制。
3. 使用邮箱唯一约束执行幂等写入。
4. 查询所选平台当前可用版本。
5. 若版本可用，创建短期下载授权并发送下载邮件。
6. 若版本不可用，保存 Waitlist 并发送确认邮件或显示确认结果。
7. 对客户端返回统一、不会泄露邮箱存在状态的结果。

### 4.2 用户反馈

提交中：

> 正在为你准备……

发送成功：

> 邮件已出发  
> 请打开邮箱查看 PhotoTend 的下载方式。如果暂时没有看到，也可以检查一下垃圾邮件。

等待版本：

> 已加入名单  
> 这个平台的体验版还在准备中，开放后我们会第一时间通知你。

重复提交时不公开说明邮箱是否已存在，仍返回语义一致的成功结果。

提交失败：

> 暂时没能提交  
> 请稍后再试。你填写的邮箱尚未被保存。

### 4.3 下载行为

邮件和成功状态中的下载入口指向网站控制的 `/download/<token>`，而不是永久安装包地址。

服务端：

1. 对 token 做摘要后查询授权记录。
2. 校验有效期、撤销状态、平台和版本。
3. 记录下载事件。
4. 为 Supabase Storage 私有对象生成短期签名地址。
5. 重定向浏览器开始下载。

原始 token 不写入日志或数据库。过期、撤销和无效 token 显示清晰的恢复路径，允许用户重新提交邮箱获取新链接。

## 5. 数据模型

### 5.1 `waitlist_entries`

- `id`
- `email`
- `platform`
- `locale`
- `source`
- `status`
- `consent_at`
- `created_at`
- `updated_at`
- `last_email_sent_at`
- `unsubscribe_token_hash`

`email` 为规范化后的唯一值。状态至少包含 `active`、`unsubscribed`、`blocked`。

### 5.2 `releases`

- `id`
- `platform`
- `version`
- `storage_path`
- `status`
- `published_at`
- `created_at`

状态至少包含 `draft`、`active`、`retired`。每个平台只能有一个默认活动版本。

### 5.3 `download_grants`

- `id`
- `waitlist_entry_id`
- `release_id`
- `token_hash`
- `expires_at`
- `revoked_at`
- `created_at`

### 5.4 `download_events`

- `id`
- `download_grant_id`
- `occurred_at`
- `result`
- 必要且最小化的安全元数据

不得长期存储完整 IP。若限流需要使用 IP，优先使用短期缓存或不可逆摘要。

### 5.5 `email_events`

- `id`
- `waitlist_entry_id`
- `provider_message_id`
- `event_type`
- `occurred_at`
- `created_at`

处理 `sent`、`delivered`、`bounced`、`complained` 和 `clicked`。Webhook 重复投递必须幂等。

## 6. 邮件设计

发件人建议：

`PhotoTend <hello@phototend.onemorejack.top>`

下载邮件主题：

> 你的 PhotoTend 体验版已准备好

正文包含：

- 欢迎与平台说明
- 版本号
- 下载按钮
- 下载链接有效期
- 必要安装提示
- 隐私说明
- 退订入口

下载或版本通知与长期营销同意分开。用户退订后不得继续发送非必要推广邮件；退信或投诉地址自动进入停止发送状态。

## 7. 安全、隐私与合规

### 7.1 安全

- 服务端邮箱校验与长度限制。
- 邮箱唯一约束和事务级幂等。
- 同一邮箱和来源 IP 的冷却及频率限制。
- 隐藏诱捕字段；机器人增长后再增加 Cloudflare Turnstile。
- Resend 发送使用幂等键。
- 下载 token 使用足够强的随机值，数据库只保存摘要。
- 下载授权有过期和撤销能力。
- Resend Webhook 必须验证签名。
- Supabase 表不允许公开读取。
- Supabase Storage bucket 保持私有。
- 密钥只放在服务端环境变量。
- 日志不得包含完整邮箱、原始 token、API key 或 Webhook secret。

### 7.2 隐私

表单旁说明：

> 提交即表示你同意我们使用此邮箱发送 PhotoTend 测试邀请、下载方式和重要版本通知。你可以随时退订。

隐私政策说明：

- 收集的数据。
- 数据用途。
- Vercel、Supabase、Resend 等处理服务。
- 数据可能通过跨境基础设施处理。
- 保存期限。
- 退订、删除和联系方法。

隐私政策内容需要与最终运营主体和实际数据流保持一致。大规模推广前应由适用地区的专业人士审核。

## 8. SEO、国际化与无障碍

- 默认根据浏览器语言选择中文或英文，同时允许手动切换。
- 每种语言有独立 metadata、canonical 与 Open Graph 内容。
- 提供 `robots.txt`、`sitemap.xml`、图标和分享图。
- 首屏核心内容服务端渲染。
- 不依赖 Google Fonts 等额外字体服务。
- 所有表单拥有可见标签、错误关联和键盘焦点。
- 颜色对比、触控尺寸和减少动态效果设置满足基本无障碍要求。
- 装饰图片不干扰屏幕阅读器，产品截图包含有意义的替代文本。

## 9. 中国大陆与海外访问

首版统一部署到 Vercel，不承诺所有中国大陆运营商下的稳定性。上线验证需要覆盖至少一种中国大陆网络和一种海外网络。

为减少跨境依赖：

- 字体与页面素材随站点部署。
- 首屏图片压缩并提供现代格式。
- 页面不依赖不必要的第三方脚本。
- 表单有超时、失败与重试状态。
- 分析工具在未确认访问质量和隐私策略前保持最小化。

如果验证结果不满足要求，再单独设计国内镜像、备案或国内托管迁移，不在首版中预先增加双部署复杂度。

## 10. 域名与部署

Vercel 项目连接当前仓库中的 `website/` 根目录。生产环境使用：

`phototend.onemorejack.top`

Vercel 添加域名后，以项目实际显示的 DNS 记录为准。在当前 DNS 服务商中添加所需 CNAME 或 TXT 记录，验证成功后确认 HTTPS 证书和生产部署。

预览部署不得连接生产邮件名单或生产安装包；应使用独立的测试配置，或确保测试记录可识别并清理。

## 11. 验收标准

### 页面与内容

- 中文和英文页面文案完整。
- 桌面和移动布局均无溢出、遮挡或不可操作元素。
- 品牌颜色、Logo 和语气与现有 PhotoTend 品牌设计一致。
- 产品能力文案不超过当前真实实现。
- 导入能力拥有独立场景区。

### Waitlist

- 有效邮箱可以提交。
- 无效邮箱收到可理解的就地错误。
- 重复提交不产生重复记录或重复风暴。
- 不同平台得到正确的下载或等待结果。
- 数据库无法被匿名公众读取。

### 邮件与下载

- 可用平台收到实际下载邮件。
- 未开放平台进入 Waitlist。
- 下载 token 支持正常、过期、撤销和无效状态。
- 私有安装包不能通过永久公开地址访问。
- 退信、投诉和点击 Webhook 可被验证并幂等处理。
- 退订后状态正确并停止非必要邮件。

### 质量

- 类型检查、Lint、单元测试和生产构建通过。
- 服务端接口、下载授权和 Webhook 有自动化测试。
- 核心页面有响应式和无障碍检查。
- 真实邮件、真实下载和生产域名链路完成一次端到端验证。
- 从中国大陆与海外网络进行访问验证并记录结果。
- 日志与客户端构建中不存在密钥或原始下载 token。

## 12. 自主执行与用户介入边界

Codex 默认自主完成：

- 设计文档、实施计划和网站代码。
- Supabase 项目、数据库、策略和 Storage 配置。
- Vercel 项目、环境变量、部署和域名关联。
- Resend 域名、API key、Webhook 和邮件模板配置。
- 自动化测试、构建、视觉检查和端到端验证。

只在以下必须由账户所有者处理的步骤集中请求用户介入：

- 登录、验证码、身份确认或 OAuth 授权。
- 新账户注册或服务条款确认。
- 域名所有权或 DNS 服务商验证。
- 付费计划、费用或账单确认。
- 需要用户决定且会实质改变范围的产品选择。

实施时应尽量把必须的用户操作合并为一次短的账户配置窗口，其余工作继续自主完成。
